# Changelog

## [Unreleased]

### Added

- Refresh-token auth with device sessions for mobile clients (G-128): `POST /api/v1/auth/login` now also returns a `refreshToken` and the `sessionId` of a newly created device session (optional `deviceName` in the request, e.g. "Pixel 9", defaults to "Unknown device"), backed by a new `device_sessions` table (migration V6) that stores only the SHA-256 hash of the refresh token; `POST /api/v1/auth/refresh` rotates the refresh token and returns a fresh 24h access JWT — replaying an already-rotated token is detected and revokes the whole session, and revoked/expired/unknown tokens answer `401` with `error.code: invalid-refresh-token`; refresh tokens live 90 days with a sliding TTL extended on every successful refresh (configurable via `POSTBOX_AUTH_REFRESH_TOKEN_TTL_DAYS`); `GET /api/v1/me/devices` lists the caller's sessions and `DELETE /api/v1/me/devices/{id}` revokes one (`404` for other users' ids, same as parcels); all of a user's sessions are revoked on password change (`PATCH /api/v1/me`) and on admin deactivation (`PATCH /api/v1/admin/users/{id}`); documented in `docs/openapi.yaml`

- On-demand refresh service: `GET /api/v1/parcels` refreshes parcels whose `last_checked_at` is older than a configurable TTL (default 30 minutes, `POSTBOX_REFRESH_STALE_AFTER_MINUTES`) before the response is returned; fresh parcels serve cached data with no carrier traffic, so repeated app opens within the TTL trigger no carrier calls

### Changed

- Each carrier now has exactly one `CarrierRateLimiter` instance shared by its adapter and the refresh/detection services (previously two independent instances double-paced the same carrier), and the limiter wait now counts against the per-carrier probe timeout, so a long queue behind one throttled carrier can no longer delay the list response unbounded
- `GET /api/v1/parcels` now refreshes stale parcels on open instead of serving cached data only
- `POST /api/v1/parcels/{id}/refresh` returns `200` with the refreshed parcel instead of `501 not_implemented`
- `POST /api/v1/parcels` without an explicit `carrier` runs detection and stores the outcome (`carrier` + `detectionMethod`) on the new parcel; an explicit `carrier` is stored as `override`
- `PATCH /api/v1/parcels/{id}` with a `carrier` records `detectionMethod: override`
- Admin user management consolidated into `PATCH /api/v1/admin/users/{id}` (deactivate/reactivate, reset password); the `POST /api/v1/admin/users/{id}/deactivate|reactivate|reset-password` sub-routes are replaced

### Security

- `POSTBOX_ENV=production` (set by the container image) refuses to boot with the shipped default `JWT_SECRET` — set `JWT_SECRET` to a strong random value
